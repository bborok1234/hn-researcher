# hn-researcher

매일 아침, Hacker News 하루치 **전부**를 읽고 **내가 지금 하고 있는 일 기준으로** 골라 정리해 주는 뉴스레터.

일반 뉴스 요약과 다른 점은 "무엇이 중요한가"가 아니라 **"내 프로젝트에 무엇이 쓸모 있는가"**로 고른다는 것이다.
그 판단 근거는 사람이 적어 넣는 관심사 목록이 아니라, **본인의 Claude Code / Codex 사용 기록**이다.
지금 무엇에 몰두하고 있는지, 무엇이 방치됐는지, 어떤 기술을 쓰는지를 기록에서 뽑아 프로필을 자동으로 만들고 매일 갱신한다.

리포트는 네 부분이다.

- **오늘의 헤드라인** — 그날 가장 중요한 발견
- **내 프로젝트에 바로 적용할 것** — 프로젝트별로, 무엇을 어떻게
- **시도해볼 기술** — 첫 실험 방법까지
- **사업화 기회** — 한국 시장에 이식하거나 선점할 만한 흐름

회사 트랙을 켜면 월요일에 **사업화 심층 리포트**가 하나 더 나온다. 기회마다 왜 지금인지, 왜 우리가 해야 하는지,
누가 돈을 내는지, 규제는 어디서 걸리는지, 2주 안에 무엇으로 검증할지를 채우게 되어 있다.

## 설치

코딩 에이전트(Claude Code)에 아래를 그대로 붙여 넣는다.

```
<REPO_URL> 를 ~/tools/hn-researcher 에 클론하고,
저장소의 INSTALL.md를 읽고 그대로 설치해줘.
설치가 끝나면 오늘 리포트를 열어서 내용이 내 실제 작업과 맞는지 같이 봐줘.
```

터미널에서 직접 하려면:

```sh
git clone <REPO_URL> ~/tools/hn-researcher
cd ~/tools/hn-researcher && ./install.sh
```

설치기가 의존성을 확인하고, 사용 기록에서 프로필을 만들고, 매일 06:44 발행으로 launchd에 등록한 뒤,
첫 리포트까지 생성해 브라우저로 띄운다. 3~5분 걸린다.

## 필요한 것

- macOS (launchd·알림 사용)
- [Claude Code](https://claude.com/claude-code) 설치 및 로그인
- python3 (표준 라이브러리만 사용, 추가 패키지 없음)
- **Claude Code나 Codex를 며칠 이상 써서 쌓인 사용 기록** — 이게 개인화의 재료다

## 설정

`config.sh`에서 바꾼다 (`config.example.sh` 복사본, 설치기가 만든다).

| 항목 | 기본값 | 설명 |
|---|---|---|
| `PUBLISH_HOUR` / `PUBLISH_MIN` | 6 / 44 | 발행 시각. 출근 전에 준비되도록 |
| `DAILY_MODEL` | `sonnet` | 일일 리포트 모델 |
| `WEEKLY_MODEL` | `fable` | 주간 심층 리포트 모델 |
| `ENABLE_COMPANY` | 1 | 회사 사업화 트랙(월요일) |
| `COMPANY_NAME` / `COMPANY_DOMAIN` | (설치 시 직접 입력) | 회사 트랙의 판단 기준 |
| `COMPANY_KEYWORDS` | 의료 키워드 | 주간 리포트가 훑을 주제 필터 |

**모델을 반드시 지정한 채로 두자.** 비워 두면 대화창의 기본 모델을 물려받아 배치가 최상위 티어로 돌면서
사용량이 조용히 몇 배로 뛴다.

## 명령

```sh
./daily.sh       # 지금 바로 발행 (오늘 치가 이미 있으면 건너뜀)
./run.sh         # 리포트만 다시 생성
./profile.sh     # 프로필 다시 생성
./uninstall.sh   # 스케줄 해제
```

추천이 잘 안 맞으면 `PROFILE.md`를 직접 고쳐도 된다. 특히 프로젝트마다 붙는 `매칭:` 키워드 줄이
1,100여 건의 목록에서 관련 글을 낚는 고리라, 여기에 단어를 더하는 것이 가장 효과가 빠르다.

## 구조

하루치 게시물이 1,100건이 넘어서, 선별·수집·작문을 한 세션에서 다 하면 비용이 감당이 안 된다
(`claude -p`는 매 턴 대화 전체를 다시 보내므로, 읽어들인 웹페이지가 턴마다 누적된다).
그래서 세 단계로 나눈다.

| 단계 | 하는 일 | 비용 |
|---|---|---|
| 1 선별 | 목록 전체를 한 번 읽고 후보 20~25건을 고른다 (도구 없음, 1턴) | ~112K 토큰 |
| 2 수집 | 파이썬이 원문·HN 댓글을 받아 텍스트로 정리 | **0** (LLM 미사용) |
| 3 작문 | 정리된 본문만 받아 리포트를 쓴다 (도구 없음, 1턴) | ~110K 토큰 |

합쳐서 회당 22만 토큰. 한 세션에서 다 하던 초기 구현은 회당 550만 토큰이었다 — **25배 차이**다.
페치를 LLM에서 코드로 옮긴 것, 선별용 목록에서 URL을 뺀 것(URL은 토큰 밀도가 높다),
`--safe-mode`로 스킬·플러그인 정의를 시스템 프롬프트에서 뺀 것이 각각 기여했다.

## 개인정보

생성되는 `PROFILE.md`와 `COMPANY.md`에는 진행 중인 사업, 고객사, 내부 판단이 그대로 담긴다.
둘 다, 그리고 모든 리포트가 `.gitignore`에 들어 있다. **포크해서 쓸 때 이 설정을 지우지 말 것.**

사용 기록은 로컬에서만 읽는다. 외부로 나가는 것은 리포트 생성을 위해 Claude API로 가는 프롬프트뿐이다.
